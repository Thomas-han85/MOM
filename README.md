# 대역 (MeetNote)

이중언어 회의 기록 앱. 준실시간 전사와 번역, 그리고 AI 회의록.
안드로이드 APK 단독 동작. 서버 없음. 데이터는 기기에만 남는다.

한국어 · 베트남어 · 영어가 섞이는 현장 회의를 대상으로 만들었다.

---

## 왜 만들었나

기존 회의록 앱들은 문장 단위로 잘라 번역해서, 맥락이 끊기고 현장 용어가 깨진다.
이 앱은 **30초 단위로 통째로 넘겨 번역**하고, **앞 구간의 꼬리를 문맥으로 함께 전달**하며,
**용어집을 강제**한다. 지연을 조금 포기하는 대신 품질을 가져온다.

---

## 사전 자료 — 회의 전에 미리 넣는다

녹음 시작 화면에 **사전 자료** 칸이 있다. 안건, 지난 회의록, 참고 문서를 그대로
붙여넣으면 두 군데에 쓰인다.

| 쓰이는 곳 | 어떻게 |
|---|---|
| **전사** | 자료에서 고유명사만 자동 추출해 인식 프롬프트에 넣는다. 첫 회의부터 정확해진다 |
| **회의록** | 전문이 그대로 들어간다. 안건이 있으면 "안건 처리 현황" 절이 생겨 항목별로 다뤄졌는지 추적한다 |

붙여넣어도 되고 파일에서 불러와도 된다.

| 형식 | 읽는 방법 |
|---|---|
| PDF | 텍스트 레이어를 먼저 뽑는다. 공짜고 즉시 끝난다 |
| 스캔된 PDF | 글자가 없으면 페이지를 이미지로 렌더링해 비전으로 읽는다. 최대 15쪽 |
| Word (.docx) | mammoth |
| 엑셀 (.xlsx/.xls/.xlsm) | SheetJS. 시트마다 표를 그대로 옮긴다 |
| 사진 · 스크린샷 | 비전으로 읽는다. 종이 회의록, 화이트보드, 손글씨 |
| 텍스트 (.txt/.md/.csv) | 그대로 |
| 한글 (.hwp) | **못 읽는다.** PDF 로 내보내거나 화면을 사진으로 찍어라 |

**OpenAI 키 하나면 전부 된다.** Anthropic 키는 필요 없다.
PDF · Word · 엑셀 읽기는 CDN 라이브러리를 그때 불러오므로 인터넷이 필요하다.
CDN 이 하나 죽으면 다음 후보로 자동으로 넘어간다.

전사 API 는 프롬프트 길이가 짧아 지난 회의록 전문을 넣을 수 없다. 그래서 고유명사만
추려서 전사에 쓰고, 전문은 회의록 작성에만 쓴다. 추출은 `gpt-4o-mini` 한 번, 약 $0.001.

시리즈 회의라면 여기서 뽑힌 고유명사가 시리즈에도 누적된다.

회의 전에 못 넣었으면 회의록 만들기 직전에 문서 탭에서 붙여넣어도 된다.
그때는 전사가 이미 끝났으므로 인식에는 반영되지 않고 정리에만 쓰인다.

**주의**: 프롬프트에 "자료 내용을 이번 회의에서 오간 말인 것처럼 옮겨 적지 마라" 가
들어 있다. 이 지시가 없으면 지난 회의록 내용이 이번 회의록에 섞여 들어온다.

---

## 회의록 형식은 고정이다

모든 회의가 같은 뼈대로 정리된다. 형식이 매번 달라지면 나중에 비교도 검색도 안 된다.

| 절 | 들어가는 것 |
|---|---|
| **결정사항** | 확정된 것만. 조건부거나 논의 중인 건 미결사항으로 간다 |
| **미결사항** | 사안 — 막힌 이유 — 결론에 필요한 것 |
| **투두리스트** | 담당자 — 할 일 — 기한. 세 칸을 반드시 채운다 |
| **일반요약** | 배경과 논의 과정. 결정과 투두는 위에서 이미 다뤘다 |

앞에 "지난 회의 후속"(시리즈일 때), 뒤에 "확인 필요"(전사가 불명확할 때)가 조건부로 붙는다.
내용이 없는 절도 생략하지 않고 "없음" 으로 남긴다.

**투두는 담당자와 기한이 안 나왔으면 "미지정" 으로 쓰게 강제했다.** 항목을 빼버리면
빠뜨린 게 안 보이지만, 미지정으로 남으면 문서 상단에 개수가 뜬다. 회의가 끝나고
누구에게 뭘 넘길지 정하지 않았다는 사실 자체가 정보다.

---

## 회의 시리즈 — 회를 거듭할수록 정확해진다

정기회의는 시리즈로 묶는다. 매 회의가 끝나면 세 가지가 다음 회의로 넘어간다.

| 넘어가는 것 | 어디에 쓰이나 |
|---|---|
| **고유명사** | 다음 회의 전사 프롬프트로 들어간다. "벤째", "응우옌" 같은 말이 회를 거듭할수록 정확히 잡힌다 |
| **미결 사항** | 다음 회의록에 "지난 회의 후속" 섹션이 생기고, 항목별로 이번에 어떻게 됐는지 추적한다 |
| **참석자·성격·번역언어** | 매번 다시 입력하지 않는다 |

회의록을 만들 때 LLM 이 데이터 블록을 함께 뱉고, 앱이 그걸 흡수해 시리즈에 저장한다.
추가 API 호출은 없다.

**누적된 고유명사는 설정에서 직접 고칠 수 있다.** 한 번 잘못 인식된 말이 목록에
들어가면 계속 그 오답이 강화되므로, 가끔 들여다보고 이상한 항목은 지워야 한다.

---

## 핵심 설계

> 녹음과 전사를 분리한다.
> 녹음기는 로컬에 저장만 하고, 전사는 별도 큐 워커가 처리한다.

이 한 줄에서 세 가지가 따라온다.

| 상황 | 동작 |
|---|---|
| 온라인 | 큐가 계속 빠짐 → 30초 지연 자막 |
| 오프라인 | 큐에 쌓임 → 연결되면 자동 재개 |
| 파일 업로드 | 파일을 잘라 같은 큐에 투입 |

오프라인 대응이 예외 처리가 아니라 기본 동작이다. 분기 코드가 없다.

## 구조

```
녹음 (Foreground Service)     ← 화면 꺼져도 유지
      │  AudioRecord 연속 PCM → 문장 경계에서 분할 (유실 0)
      │  15초까지 채운 뒤 첫 침묵에서 자름. 45초 넘으면 강제 분할.
      ▼
   IndexedDB 큐               pending → sent → done / failed
      │  온라인일 때만 드레인, seq 순서 보장
      ▼
   gpt-4o-transcribe          앞 구간 꼬리를 prompt 로 전달
      │
      ▼
   gpt-4o-mini                용어집 + 직전 구간 문맥으로 번역
      │
      ▼
   Claude                     전체 전사문 → 회의록
```

## 처음 세팅

### 1. 리포 올리기

```bash
git init
git add .
git commit -m "meetnote v1"
git branch -M main
git remote add origin https://github.com/Thomas-han85/meetnote.git
git push -u origin main
```

### 2. APK 받기

푸시하면 GitHub Actions 가 알아서 빌드한다. 안드로이드 스튜디오 필요 없다.

1. 리포 → **Actions** 탭
2. 최근 `APK 빌드` 실행 클릭
3. 아래 **Artifacts** 에서 `meetnote-apk` 다운로드
4. 압축 풀고 폰으로 옮겨 설치 (출처를 알 수 없는 앱 설치 허용 필요)

수동 실행하려면 Actions 탭에서 `Run workflow`.

### 3. 앱에서 키 넣기

설정에서 OpenAI 키와 Anthropic 키를 입력한다. 기기에만 저장된다.
**용어집과 참석자를 채울 것.** 여기가 품질이 갈리는 지점이다.

```
적산 = bóc tách khối lượng = quantity takeoff
펀치리스트 = danh sách lỗi = punch list
공정률 = tiến độ = progress rate
```

참석자는 이름·역할·언어·말투·자주 쓰는 말을 적는다. 구체적일수록 회의록에서
발언자가 정확하게 붙는다.

```
한경석 / 전략기획 / 한국어 / 결론부터 말하고 숫자를 먼저 댄다 / 적산, 공정률, 리스크
Nguyen Van A / 벤째 현장소장 / 베트남어 / 질문을 되묻는 편 / tiến độ, an toàn
```

## 로컬에서 굴리기

```bash
npm install
npm run serve          # 브라우저에서 확인. 녹음은 되지만 화면 끄면 끊긴다.
npm run android:init   # 안드로이드 프로젝트 생성 + 네이티브 주입 (최초 1회)
npm run android:build  # APK 빌드
```

`android/` 는 커밋하지 않는다. `scripts/apply-native.js` 가 매번 재현한다.
`www/index.html` 만 고치면 되고, 고친 뒤엔 `npm run android:sync`.

## 검증 체크리스트

APK 받고 처음 할 것.

- [ ] 화면 끄고 30분 녹음 → 구간 누락 0개
- [ ] 구간 경계에서 단어가 잘리는지 (AudioRecord 방식이라 안 잘려야 정상)
- [ ] 일시정지 → 5분 뒤 재개 → 앞뒤가 자연스럽게 이어지는지
- [ ] 참석자 프로필 등록 후 회의록에서 발언자가 맞게 붙는지
- [ ] "지금 중요" 누른 구간이 요약에 반영되는지
- [ ] 같은 시리즈로 2회 이상 하고, 2회차 전사에서 고유명사가 더 잘 잡히는지
- [ ] 2회차 회의록에 "지난 회의 후속" 이 나오는지
- [ ] 회의록 상단 지표에 결정·미결·투두 개수가 맞게 뜨는지
- [ ] 담당자가 안 정해진 일이 "담당 미지정" 으로 잡히는지
- [ ] 사전 자료에 안건을 넣고 "안건 처리 현황" 이 나오는지
- [ ] 사전 자료의 고유명사가 실제로 더 잘 인식되는지
- [ ] 사전 자료 내용이 회의록 본문에 잘못 섞여 들어가지 않는지
- [ ] PDF · Word · 엑셀을 각각 올려 내용이 제대로 들어오는지
- [ ] 스캔된 PDF 를 올려 비전으로 읽히는지
- [ ] 비행기모드로 10분 녹음 → 연결 복구 시 자동 전사
- [ ] 한국어·베트남어 섞인 대화 → 인식 정상
- [ ] 앱 강제 종료 후 재실행 → 큐 상태 복구
- [ ] 번역 품질이 기존 도구보다 나은지 (안 나으면 청크 길이를 45초로)
- [ ] 60분 녹음 시 배터리 소모율

## 알려진 제약

- 성문(voiceprint) 등록은 없다. 화자 추정은 참석자 프로필의 역할·말투·어휘를
  근거로 회의록 단계에서 LLM 이 한다. 근거가 약하면 "발언자 불명"으로 남긴다.
  정확도가 부족하면 Picovoice Eagle + Falcon 을 얹는 것이 다음 단계다.
- 일시정지 구간은 당연히 녹음되지 않는다. 타임스탬프는 실제 녹음 길이 기준이다.
- 브라우저로 열면 화면 꺼짐 시 녹음이 끊긴다. APK 에서만 해결된다.
- 전사가 끝난 오디오는 자동 삭제된다. 원본 보관이 필요하면 `keepAudio` 플래그를 켜야 한다.
